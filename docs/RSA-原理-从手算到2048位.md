# RSA 原理：从 61×53 的手算，到真实 2048 位密钥

> 演示代码：`src/main/java/com/ds/crypto/RsaFromScratchDemo.java`（7 段，22 项自检）
> 一键复现：`.\scripts\run-rsa-principles-demo.ps1`
> 原始输出：`docs/rsa-principles-raw.txt`
> 实跑环境：OpenJDK 17.0.12；脚本退出码 0，22 项自检全过。
>
> 数值说明：小素数部分的数字是固定的（可手算核对）；2048 位部分的耗时、CRT 加速比每次运行略有波动。
>
> 如果离散数学基础薄：先看 [离散数学最小知识包-只为看懂数字签名.md](<docs/离散数学最小知识包-只为看懂数字签名.md>)，
> 那里只保留"会用就够"的四个点（模逆、欧拉定理、CRT、平方-乘），不需要任何证明。

数字签名之所以难懂，往往不是签名本身难，而是**它默认你已经知道 RSA 在干什么**。
RSA 只需要三样前置知识：

1. **模运算**：`a ≡ b (mod n)` 就是"除以 n 的余数相同"；
2. **模逆元**：找一个 `d` 使 `e·d ≡ 1 (mod φ)`，相当于"模世界里的倒数"；
3. **单向陷门**：人人都能做的运算（乘方）里，藏一个只有你知道的"反向开关"（私钥）。

下面把这三样全部用手算跑一遍，再上 2048 位。

---

## 0. 四个数字，各是什么角色

| 符号 | 名字 | 例子（本文小例子） | 公开吗 | 作用 |
|---|---|---|---|---|
| `p, q` | 两个大素数 | 61、53 | **保密** | 生成密钥的来源 |
| `n = p·q` | 模数 | 3233 | 公开 | 所有运算的模 |
| `φ(n) = (p-1)(q-1)` | 欧拉函数 | 3120 | **保密** | 算 d 用；等价于 p、q |
| `e` | 公钥指数 | 17（实际 65537） | 公开 | 加密、验签 |
| `d` | 私钥指数 | 2753 | **保密** | 解密、签名 |

**公钥 = (n, e)，私钥 = (n, d)。** 加密是 `c = m^e mod n`，解密是 `m = c^d mod n`。
数字签名只是把这两个指数**换个方向用**：私钥算 `m^d` 得到签名，公钥算 `s^e` 验证。

## 1. 手算全流程（p=61, q=53）

### 1.1 选素数，算 n

```text
第 1 步 选两个素数：p = 61，q = 53
第 2 步 模数 n = p*q = 3233
第 3 步 欧拉函数 φ(n) = (p-1)(q-1) = 3120
```

`φ(n)` 的含义：`1..n-1` 里与 `n` 互素的数的个数。对两个素数的乘积，
`φ(pq) = (p-1)(q-1)` —— 这一步之所以能算，**正是因为知道 p、q**；外人只看到 3233，要拆回 61×53
（2048 位时是"拆一个 617 位十进制数"）就是 RSA 的安全性所在。

### 1.2 选 e

```text
第 4 步 公钥指数 e = 17（通常取 65537，这里为了手算取小的）
```

条件：`1 < e < φ(n)` 且 `gcd(e, φ(n)) = 1`。真实系统固定取 `65537 = 2^16+1`，
因为它的二进制 `1 0000 0000 0000 0001` 只有 2 个 1 —— 平方-乘算法只要 16 次平方 + 1 次乘法，
加密/验签非常快，同时足够大以避免小指数攻击。

### 1.3 求 d：扩展欧几里得

要求 `17·d ≡ 1 (mod 3120)`。扩展欧几里得一路做带余除法：

```text
3120 = 183 * 17 + 9      (1)
17   = 1   * 9  + 8      (2)
9    = 1   * 8  + 1      (3)
8    = 8   * 1  + 0      (4)   ← 余数 0，停；上一行余数 1 就是 gcd
```

然后把余数 1 逐层回代成 17 和 3120 的组合（**-367 就是这么来的**）：

```text
(3)  1 = 9 - 1*8
     代入 (2) 8 = 17 - 1*9：      1 = 2*9 - 17
     代入 (1) 9 = 3120 - 183*17： 1 = 2*3120 - 367*17
=> 17 * (-367) ≡ 1 (mod 3120)
=> d = -367 + 3120 = 2753
```

验证：`17 × 2753 = 46801 = 15 × 3120 + 1`。所以 **d = 2753**。

不想做代数回代时用表格法：每行满足 `r = s·17 + t·3120`，只记 `s`，
规则是"下一行的 s = 上一行的 s − 商 × 当前行的 s"：

| r | 商 | s（17 的系数） |
|---|---|---|
| 3120 | – | 0 |
| 17 | – | 1 |
| 9 | 183 | −183 |
| 8 | 1 | 184 |
| 1 | 1 | **−367** |

演示程序第【4】段会把这条除法链、回代、表格法、验证全部打印出来（`docs/rsa-principles-raw.txt`）。

这一步是密钥生成的核心：`d` 就是 `e` 在模 `φ(n)` 下的逆元。
真实密钥生成里，`p`、`q` 各 1024 位，`φ` 是 2048 位，同样用扩展欧几里得求 `d`。

### 1.4 加密：c = m^e mod n（平方-乘逐步）

m = 65（字符 `'A'`），e = 17 = `0b10001`。从最高位开始，每读一位先平方，遇到 1 再乘底数：

```text
m^e：底数 65，指数 17 = 0b10001（5 位）
  bit 1/5 = 1 -> 平方 + 乘底数 -> 65
  bit 2/5 = 0 -> 平方 -> 992
  bit 3/5 = 0 -> 平方 -> 1232
  bit 4/5 = 0 -> 平方 -> 1547
  bit 5/5 = 1 -> 平方 + 乘底数 -> 2790
  共 5 次平方、2 次乘底数（naive 要 17 次乘法）
=> 密文 c = 2790
```

手算核对（每步都是"平方后 mod 3233"）：

```text
65^2 = 4225      -> 992
65^4 = 992^2     -> 1232
65^8 = 1232^2    -> 1547
65^16 = 1547^2   -> 789
65^17 = 789*65   -> 2790
```

### 1.5 解密：m = c^d mod n

```text
c^d：底数 2790，指数 2753 = 0b101011000001（12 位）
  ... 12 次平方 + 5 次乘底数 ...
=> 明文 m' = 65（'A'）
```

整条链路：`m -> m^e -> c -> c^d -> m`。中间没有任何"查表"或"隐藏规则"，全靠模幂运算。

## 2. 为什么 d 能把 m 还原（这部分教材通常跳过）

要证：`(m^e)^d ≡ m (mod n)`。

```text
步骤 1：e·d ≡ 1 (mod φ(n))  ==>  e·d = 1 + k·φ(n)   （本文 e·d = 46801 = 1 + 15*3120，k = 15）
步骤 2：c^d = (m^e)^d = m^(e·d) = m^(1 + k·φ(n)) = m · (m^φ(n))^k
步骤 3：欧拉定理：gcd(m, n) = 1 时，m^φ(n) ≡ 1 (mod n)
步骤 4：代入得 m · 1^k = m (mod n)。证毕。
```

**步骤 2 和步骤 4 到底做了什么？** 只有两次替换，都是初等规则：

1. `m^(1+kφ) = m · (m^φ)^k`：指数法则 `m^(A+B) = m^A·m^B`、`m^(kφ) = (m^φ)^k`，和模运算无关；
2. `(m^φ)^k ≡ 1^k`：欧拉定理给 `m^φ ≡ 1 (mod n)`，而"同余"在乘方下保持——
   若 `a ≡ b (mod n)`，则 `a^k ≡ b^k (mod n)`；再 `1^k = 1`。

**用最小数字手算一遍**（n=7, φ(7)=6, m=2, k=2）：

```text
2^6 = 64 = 9*7 + 1        => 2^6 ≡ 1 (mod 7)       ← 欧拉定理
2^(1+2*6) = 2^13 = 8192 = 2*(2^6)^2 = 2*4096
按 m*(m^φ)^k 算：2 * 1^2 = 2
直接算：8192 = 1170*7 + 2 => 2^13 mod 7 = 2
两者一致。
```

换成 RSA 的数字（m=65, n=3233, φ=3120, e·d=46801）：`65^3120 mod 3233 = 1`，
所以 `65 * 1^15 = 65`，直接算 `65^46801 mod 3233` 也等于 65（上面演示程序第【2】段有实测）。

实测 `m^φ(n) mod n`（本文参数，φ=3120，n=3233）：

```text
m = 2    -> m^3120 mod 3233 = 1
m = 3    -> m^3120 mod 3233 = 1
m = 65   -> m^3120 mod 3233 = 1
m = 1000 -> m^3120 mod 3233 = 1
```

### 2.1 一个常见疑问：m 和 n 不互素怎么办？

欧拉定理要求 `gcd(m, n) = 1`，而现实中 `m` 可以是 0 到 n-1 的任何数（比如 `m = p`）。
实测：

```text
取 m = p = 61（与 n 不互素，欧拉定理不适用）：
  m^φ(n) mod n = 1220 ≠ 1（欧拉定理确实不成立）
  但 m^(e·d) mod n = 61，依然还原
```

原因是中国剩余定理（CRT）：分别看模 `p` 和模 `q`——
`mod p` 两边都是 0；`mod q` 两边都是 `m`；两个同余式合并就对所有 `m` 成立。
（`m` 只能是 `p` 或 `q` 的倍数才会不互素，而 `m < n = pq` 时这种情况极少，但证明必须照顾到。）

**CRT 具体在拼什么？** 给它两个余数，它给出 `0 ≤ x < pq` 里唯一的 x：

```text
x ≡ 0 (mod 61)、x ≡ 1 (mod 53)，M = 61×53 = 3233
零件1（管 mod 61）：53 × 53⁻¹ mod 61 = 53 × 38 = 2014   （mod 61 为 1，mod 53 为 0）
零件2（管 mod 53）：61 × 61⁻¹ mod 53 = 61 × 20 = 1220   （mod 61 为 0，mod 53 为 1）
x = 0×2014 + 1×1220 = 1220
```

规则是：`Mi = M / 除数`，再乘上 `Mi` 自己的逆元。之所以能"任意两个余数都拼得出来"，
是因为 `p`、`q` 互素；不互素时会矛盾，比如 `x ≡ 0 (mod 4)` 且 `x ≡ 1 (mod 6)` 无解（一个要求偶数、一个要求奇数）。

**CRT 加速私钥运算**就是同一套拼法：先在 `p`、`q` 上各算一半，再拼回去——

```text
m1 = 2790^2753 mod 61 = 4（= 65 mod 61）
m2 = 2790^2753 mod 53 = 12（= 65 mod 53）
qInv = 53⁻¹ mod 61 = 38
h = qInv × (m1 − m2) mod 61 = 38 × (4−12) mod 61 = 1
m = m2 + h×q = 12 + 1×53 = 65        ✓ 与直接算 c^d mod n 一致
```

两个 1024 位运算比一个 2048 位运算快约 3 倍（实测 4.491 ms → 1.456 ms）。

## 3. 为什么快：平方-乘 + CRT

### 3.1 平方-乘（快速幂）

`m^e mod n` 最笨的做法是乘 `e` 次；平方-乘把它压到 `O(log e)` 次模乘：

- 指数 17（5 位）：**5 次平方 + 2 次乘法**，naive 要 17 次；
- 2048 位私钥的 `d` 约 2045~2047 位：**约 2046 次平方 + 1000 次左右乘法**，naive 要 10^616 次。

这就是为什么 RSA 能实用：2048 位的一次解密只要几毫秒。

### 3.2 CRT 加速约 3 倍

私钥运算 `c^d mod n` 可以用中国剩余定理拆成两个一半长度的运算：

```text
m1 = c^dP mod p
m2 = c^dQ mod q
h  = qInv · (m1 - m2) mod p
m  = m2 + h·q
```

实测（2048 位，10 次平均）：

```text
直接算 c^d mod n      : 4.491 ms
CRT: 模 p、模 q 再合并 : 1.456 ms
加速比约 3.1 倍
```

代价是私钥要多存 5 个数：`p, q, dP, dQ, qInv`（`dP = d mod (p-1)` 等）。
JDK 的 `RSAPrivateCrtKey` 就带这五个参数，`Cipher` 内部自动走 CRT。

## 4. 为什么安全：安全性 = 分解 n 的难度

RSA 的关系链是：

```text
n = p·q      --(分解难)-->  p, q
p, q         --(直接算)-->  φ(n) = (p-1)(q-1)
φ(n), e      --(扩展欧几里得)-->  d
d            --(公开的 e)-->  解密任何密文、伪造任何签名
```

演示里把"攻击者知道了 φ(n)"当作前提，结果一步到位：

```text
假设攻击者暴力枚举出 φ(n) = 3120（真实世界做不到）：
  他立刻能算 d' = e^-1 mod φ(n) = 2753 —— 就是私钥 d
  用 d' 解密 c = 2790 -> 65（原文 65）
```

所以 **φ(n) 就是秘密本身**，而 φ(n) 只依赖 p、q，于是安全性落在"分解 n"上。
（反过来也成立：已知 `d` 能在多项式时间内分解 `n`，只是教材通常不讲。）

规模感（公开记录）：

| 密钥长度 | 状态 |
|---|---|
| 512 位 | 1999 年就被业余算力攻破 |
| 1024 位 | 已不安全（NIST 2013 起不再允许新用途） |
| **2048 位** | **至今未被分解，当前公认底线** |
| RSA-250（829 位十进制） | 2020 年被分解，约 2700 核·年 |

注意：RSA 的安全**不依赖算法保密**（算法早公开了），只依赖"分解 n 的计算量"。
如果有朝一日大整数分解或量子计算（Shor 算法）变得可行，RSA 就整体失效——所以才有后量子密码（ML-KEM/ML-DSA）。

## 5. 真实的密钥怎么生成

1. **找两个大素数**：随机生 1024 位奇数，用 Miller-Rabin 素性测试反复试，直到通过（约几百次尝试）；
2. **算 n、φ**；必须检查 `n` 的位数正好是 2048（否则重新生成）；
3. **选 e = 65537**，检查 `gcd(e, φ) = 1`；
4. **求 d = e^-1 mod λ(n)**——工程实现通常用 `λ(n) = lcm(p-1, q-1)` 而不是 `φ(n)`，
   两者都能让 `e·d ≡ 1` 成立，但 `λ` 更小、`d` 更短，还满足 FIPS 186-4 的要求；
5. **预计算 CRT 参数** `dP, dQ, qInv`。

实测（2048 位）：

```text
生成 2048 位密钥耗时: 353 ms
n 位数: 2048 位（十进制约 617 位）
e = 65537
d 位数: 2045 位（几乎和 n 一样长，私钥运算慢就慢在这里）
CRT 参数: p 1024 位, q 1024 位, dP 1024 位, dQ 1021 位
```

## 6. 裸 RSA 不能直接用

教科书公式（本文第 1 节）只适合教学。直接用它做产品会踩：

| 问题 | 后果 | 标准做法 |
|---|---|---|
| `m` 必须 `< n` | 2048 位密钥只能加密 255 字节，签名同理 | 加密用"混合加密"（RSA 只加密一把 AES 密钥），签名先 hash |
| 没有随机性 | 同样明文永远同样密文，可比较、可重放 | OAEP 填充（随机化） |
| 可乘性 | 密文可乘、明文可乘 | OAEP / PSS 填充，拒绝结构不对的输入 |
| 填充错误信息泄漏 | Bleichenbacher 1998 的选择密文攻击 | 恒定错误响应、使用 OAEP |
| 裸签名可伪造 | 两条签名相乘伪造第三条 | 签名必须先 hash 再填充（PSS / PKCS#1 v1.5） |

JDK 里对应的是：

```java
// 加密（公钥加密、私钥解密，带随机化填充）
Cipher.getInstance("RSA/ECB/OAEPWithSHA-256AndMGF1Padding");
// 签名（私钥签、公钥验，带随机盐）
Signature.getInstance("RSASSA-PSS");
```

（`RsaJdkDemo.java` 演示了 OAEP + 混合加密；`DigitalSignatureDemo.java` 演示了 PSS 签名。）

## 7. RSA 与数字签名：同一套运算，相反的方向

| 用途 | 谁用什么指数 | 公式 | 谁能做 |
|---|---|---|---|
| 加密 | 公钥 `e` 加密，私钥 `d` 解密 | `c = m^e`，`m = c^d` | 加密人人可做，解密只有私钥持有者 |
| 签名 | 私钥 `d` 签，公钥 `e` 验 | `s = H(m)^d`，验 `s^e == H(m)` | 签名只有私钥持有者，验证人人可做 |

所以"签名 = 用私钥加密"这个说法**在指数方向上是贴合事实的**，但它省掉了 hash 与填充，
照字面实现会得到只能签 255 字节、且可被伪造的东西（详见
[数字签名-教材没说的部分.md](<docs/数字签名-教材没说的部分.md>)）。

一张图记住：

```text
                公钥 e（公开）                私钥 d（保密）
加密/验签   ──  m^e  ──>  c / 验证通过  <──  c^d  ──  解密/签名
                 ↑ 任何人都能做                ↑ 只有私钥持有者能做
```

## 8. 一页速查

```text
密钥生成:  p,q 素数 -> n=pq -> φ=(p-1)(q-1) -> e=65537 -> d=e^-1 mod φ
加密:      c = m^e mod n          (m < n，实际用 OAEP + 混合加密)
解密:      m = c^d mod n          (实际用 CRT 加速，约 3 倍)
签名:      s = H(m)^d mod n       (先 hash 再填充)
验签:      s^e mod n == H(m)      (返回 true/false)
安全:      分解 n 难；φ、d、p、q 任何一个泄露都等同于私钥泄露
```

常见误区：

| 误区 | 事实 |
|---|---|
| RSA 在"加密每个字节" | 它加密的是"小于 n 的整数"；实际是混合加密，RSA 只加密 AES 密钥 |
| n 越大越慢是线性的 | 模幂是 `O(log d)` 次模乘，每次模乘 `O(n²)`；2048 位比 1024 位慢 5~8 倍 |
| 私钥就是 `d` | 实际私钥还包含 `p, q, dP, dQ, qInv`（CRT 加速）；`d` 单独也能用，但慢 |
| 加密和签名可以混用 | 填充不同（OAEP vs PSS）、安全假设不同，不能混 |
| 知道 e 就能推 d | 需要分解 n；这正是 RSA 的假设 |
