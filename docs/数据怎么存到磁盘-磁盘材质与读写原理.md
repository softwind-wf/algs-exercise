# 从磁盘材质讲到一行数据

前面两份笔记讲的都是"页"和"文件字节"。这一份再往下：**盘片是用什么做的、0 和 1 到底以什么物理形态存在、读写头凭什么能读写、SSD 又是怎么存电荷的。**

先说清楚一件事：本机实测的磁盘是 **NVMe SSD（型号 `HFM512GD3JX013N`）**，里面**没有盘片、没有磁头、没有寻道**。但数据库教材（《数据库系统概念》讲磁盘那一章）讲的大多是机械硬盘，所以两种介质都讲，并标清楚哪些是本机的、哪些是教材里的。

---

## 一、机械硬盘（HDD）：材质

一块 2.5 英寸盘片，从下往上是一层层镀上去的：

```
┌─────────────────────────────────────────┐
│  润滑层        ~1-2 nm   （减少磁头磨损）  │
│  碳保护层 DLC  ~2-3 nm   （类金刚石碳，防划）│
│  磁性记录层    ~10-20 nm （CoCrPt 合金晶粒）│
│  软磁底层 SUL  ~50-100 nm（引导写磁场回路） │
│  镍磷层 NiP    ~10 µm    （把基板磨平）    │
│  基板          铝合金 或 玻璃（1.27 mm）   │
└─────────────────────────────────────────┘
```

关键点：

1. **基板本身不存数据**，只是"托盘"。铝合金便宜、玻璃更平更硬（抗冲击、抗热变形，企业盘常用）。
2. **真正存数据的是 CoCrPt（钴铬铂）合金薄膜**。它是溅射上去的，由**几纳米大小的磁晶粒（grain）**组成，晶粒之间用氧化物隔开（防止互相干扰）。晶粒太小会遇到"超顺磁极限"——室温热扰动就能把磁化方向打乱，数据自己就没了。这是硬盘密度继续提高的物理天花板，也是 HAMR（热辅助磁记录）这类技术要解决的问题。
3. **一个 bit 不是一个原子**，而是一小片区域（bit cell），里面几百个晶粒**磁化方向一致**才算一个稳定的 0 或 1。

## 二、机械硬盘：0 和 1 是什么

现代硬盘用**垂直磁记录（PMR）**：磁化方向垂直于盘面，朝上 = 1，朝下 = 0（或者反过来）。

```
   盘片俯视（沿磁道方向）        侧视（垂直磁化）

   ┌───┬───┬───┬───┬───┐           ↑   ↑   ↓   ↓   ↑
   │ ⊕ │ ⊖ │ ⊕ │ ⊕ │ ⊖ │          ┌─┐ ┌─┐ ┌─┐ ┌─┐ ┌─┐   ← 记录层
   └───┴───┴───┴───┴───┘          └─┘ └─┘ └─┘ └─┘ └─┘
    1   0   1   1   0             朝上 朝下 ...
```

写进去之后，**不需要通电也能保持**——这就是"非易失存储"。磁性材料有剩磁（remanence），只要不施加超过矫顽力（coercivity，Hc）的反向磁场，磁化方向就稳定。

## 三、机械硬盘：写头怎么把 0 变成 1

写头是**单极磁头**（single-pole head）：一个主磁极（main pole）+ 一个返回磁极（trailing shield），绕在上面的线圈通电。

```
        线圈电流 →
    ┌──────────────┐
    │   主磁极 N    │
    └──────┬───────┘
           │ 强磁场垂直穿进记录层
    ═══════╪═══════════════  记录层
           │ 从软磁底层 SUL 回来
    ┌──────┴───────┐
    │   返回磁极     │
    └──────────────┘
```

- 线圈里通**方波脉冲电流**，主磁极尖端产生局部强磁场；
- 这个磁场必须**超过介质的矫顽力**（约 5000–8000 Oe），否则翻转不过来，写不进去；
- 电流方向决定磁场方向，也就决定写 1 还是写 0；
- 脉冲边沿越陡，bit 边界越锐利，密度就能越高。

写头有个副作用：写的时候会把相邻磁道边缘也"蹭"到一点（相邻轨道干扰 / ATI），所以硬盘的磁道之间要留保护间隔，这也是容量损失来源之一。

## 四、机械硬盘：读头怎么把磁场变成 0/1

读头**不产生磁场**，它感知磁场。现代读头用的是**磁阻效应**：

- **GMR（巨磁阻）**：Fe/Cr 多层膜，两层铁磁层的磁化方向**相同**时电阻小，**相反**时电阻大，变化 10%–20%。1988 年发现，2007 年诺贝尔物理学奖。
- **TMR（隧道磁阻）**：两层铁磁层夹一层 1nm 的 MgO 绝缘势垒，电子靠隧穿通过；磁化方向改变，隧穿概率（电阻）变化可达 100%–200%。2007 年后成为主流。

```
读头：恒定电流 I 流过磁阻元件
   盘片上的 bit 磁场 → 改变读头自由层的磁化方向
        → 电阻 R 变化 → 电压 U = I × R 变化
            → 放大 → 数字化 → PRML/Viterbi 解码 + ECC 纠错 → 0/1
```

**读头不接触盘片**：靠盘片高速旋转带动的空气，让磁头"飞"在盘面上方。现代飞高只有 **5–10 nm**（比头发丝细约一万倍）。飞太高信号太弱，飞太低就会撞盘（head crash），整块盘报废。

## 五、机械硬盘：几何与时间成本

```
盘片俯视：
        ╭──────────────────╮
      ╭─┤   磁道 track      │╮
     │  │  ╭────────────╮   │ │      一个扇区 sector：
     │  │  │ 扇区 512B/4KB│   │ │      磁道上的一小段弧
     │  │  ╰────────────╯   │ │
     │  ╰───────────────────╯ │
      ╰───────────────────────╯
   同一半径上、不同盘面的所有磁道 → 柱面 cylinder
```

定位一次数据要两步：

| 步骤 | 动作 | 典型时间 |
| --- | --- | --- |
| 寻道 | 音圈马达（VCM）把磁头臂移到目标磁道 | 平均 8–10 ms |
| 旋转延迟 | 等目标扇区转到磁头下面 | 7200 rpm → 一圈 8.3 ms，平均 4.2 ms |
| 传输 | 读这个扇区 | 微秒级 |

**所以 HDD 上一次随机读约 10–15 ms，其中 99% 的时间花在"找地方"，不是"搬数据"。** 顺序读就便宜得多（不用反复寻道），能跑到 150–250 MB/s。这就是数据库一切"按页读、缓存、批量写"设计的源头。

（4KB 扇区：物理扇区从 512B 提到 4KB，是为了 ECC 效率更高、格式开销更小；"512e" 是让老系统还能按 512B 寻址的兼容层，介质实际还是 4K——本机 SSD 也是这个情况。）

## 六、SSD：没有磁头，全是电荷

SSD 的存储单元是**浮栅晶体管**（2D NAND）或**电荷陷阱**（3D NAND，主流）。核心结构：

```
        控制栅 CG
          │
    ┌─────┴─────┐
    │  浮栅 FG   │  ← 电子被关在这层绝缘体包围的"笼子"里
    └─────┬─────┘
   ┌──────┴──────┐
   │ 源极 S  漏极 D│
   └─────────────┘
        衬底
```

- 往浮栅里注入电子 → 控制栅下面更难形成导电沟道 → **阈值电压 Vth 升高**；
- 读出：给控制栅一个参考电压，看沟道导不导通，就知道 Vth 在哪个区间；
- **一个单元能存几个 bit，取决于能分出几个 Vth 区间**：

| 类型 | 每单元 bit | Vth 区间 | 写速度 | 寿命（P/E 次数） |
| --- | --- | --- | --- | --- |
| SLC | 1 | 2 | 快 | ~10 万 |
| MLC | 2 | 4 | 中 | ~1 万 |
| TLC | 3 | 8 | 慢 | ~1000–3000 |
| QLC | 4 | 16 | 很慢 | ~几百 |

**写（编程）**：增量步进脉冲编程（ISPP）——一次次加一点电压，把 Vth 推到目标区间，直到落进去为止。写一页 4–16KB 要几十到几百微秒。

**擦**：不是按字节，是**按块**（block，128–512 页，几 MB）。加约 20V 高压，靠 FN 隧穿把电子抽出浮栅。擦一个块要几百微秒到几毫秒。

**写之前必须先擦**——这就是 SSD 所有麻烦的根源：你要改 1 个字节，控制器可能要先搬走整个块里的有效数据、擦掉、再写回去。这叫**写放大**，由控制器里的 **FTL（闪存转换层）** 负责调度：逻辑扇区 → 物理页的映射、垃圾回收（GC）、磨损均衡。

另外两个物理事实：

- **掉电保持有限**：电荷会慢慢泄漏，TLC/QLC 盘长期不通电（几年）可能丢数据；高温更糟。
- **寿命有限**：每个块能擦写的次数固定，写满全盘一次算一个 P/E 周期。

## 七、把物理换成数字（本机实测）

`scripts/measure-disk-physics.ps1` 在一台 NVMe SSD 上实测（绕过页缓存用 `FILE_FLAG_NO_BUFFERING`，同步单发）：

| 读法 | 每次 I/O | 折合带宽 | 说明 |
| --- | --- | --- | --- |
| 页缓存命中 8KB 随机 | 37.6 µs | 208 MB/s | 纯内存拷贝 + 系统调用 |
| 设备读 8KB 顺序 | 122.3 µs | 63.9 MB/s | 真的要过设备 |
| 设备读 8KB 随机 | 177.7 µs | 44.0 MB/s | 随机比顺序慢 1.45 倍 |
| 设备读 4KB 随机 | 177.6 µs | 22.0 MB/s | 一个物理扇区 |
| 设备读 128KB 顺序 | 168.4 µs | 742.4 MB/s | 单次耗时差不多，搬的数据多 32 倍 |

（每行都含约 20–30 µs 的 Windows 系统调用固定开销，所以绝对值偏高；看倍数关系。）

三个结论：

1. **成本按"次数"算，不按"字节"算**：4KB 和 128KB 的单次耗时几乎一样（178 vs 168 µs），带宽却差 34 倍。
2. **SSD 上随机和顺序差得不多**（1.45 倍，因为没有寻道），但 HDD 上是 100 倍量级（10ms vs 0.1ms）。
3. **缓存命中比读设备快 5 倍**（37.6 vs 177.7 µs），这还是 SSD；HDD 上是几百倍。

一页 8KB 装 33 行：一次 I/O 带回 33 行；按行读就要 33 次 I/O。**这就是"数据库按页读写"的全部理由。**

## 八、物理事实怎么变成数据库设计

| 物理事实 | 数据库里的对策 |
| --- | --- |
| 扇区 512B/4KB，一次 I/O 有固定成本 | 页取扇区的整数倍（PG 8KB = 2×4KB），一次读一整页 |
| HDD 寻道 8–10ms、SSD 也有固定开销 | 缓冲池（shared_buffers）把热页留在内存；B+ 树一页索引几层就定位 |
| 内存易失、掉电就没 | 提交前把 WAL `fsync` 到盘；数据页之后慢慢刷 |
| SSD 写前要擦、擦除块大、写放大 | 顺序追加写 WAL、脏页批量回写、VACUUM 批量回收，避免一行一行写 |
| 4KB 物理扇区 | 文件/页 4KB 对齐，避免"读 1 字节碰 2 个扇区"的读放大 |
| 介质有 ECC、有坏块 | 页校验和（pd_checksum）、WAL 的 FPW（整页写）、备份与 PITR |

## 九、从一块 NAND 电荷到一行数据

```
浮栅里的电子数量（Vth 落在哪个区间）
    ↓ 读出 0/1
NAND 页 4KB / 16KB 的比特流
    ↓ 控制器 FTL 映射
文件里的字节（偏移、extent）
    ↓ 用户态 read()
PostgreSQL 8KB 页（页头 + 行指针 + 元组区）
    ↓ 行指针 lp_off / lp_len
244 字节的元组（t_xmin / t_xmax / ctid / 三列）
    ↓ schema
id=1, name='student1', pad='xxx...'
```

每一层都只是"按某种规则解释下面一层的字节"。**没有哪一层是"真正的数据"——数据在最底下就是电荷和磁化方向。**
