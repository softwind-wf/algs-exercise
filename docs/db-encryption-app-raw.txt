===== ② 应用侧密钥（演示：每次运行随机生成，真实系统放 KMS/KeyStore） =====

  S004  刘洋  13700137000

===== ⑥ 盲索引：不存明文也能等值查询，而且走索引 =====
  HMAC(13900001111) = 13fe417bdf7549fe1298adbace3446261d6b438f756df794ff77bd58c745601a
  EXPLAIN: type=ref key=idx_phone_bidx rows=2 Extra=Using where; Using index
  命中: [S001, S003]（S001 与 S003 同号）
  对照：逐行解密 5 行才能过滤，命中 [S001, S003]；数据量越大差距越大。
  WHERE phone_ct LIKE '%138%' → 0 行（密文里搜不到明文）。

===== ⑦ 篡改密文：GCM 认证失败，应用拿不到「垃圾明文」 =====

===== 完成 =====
  结论：数据库只拿到密文 + 随机数 + 标签 + 盲索引 + 包好的 DEK；
        明文、DEK、KEK 都不在库里。代价是应用要自己做加解密与密钥管理。
