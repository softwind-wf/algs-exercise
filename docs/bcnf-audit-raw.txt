【3】完全 BCNF 分解推演(3NF 与 BCNF 分歧的两个经典例, 结论由程序算, 不靠背)

   ● 例 A(3NF 放行、BCNF 拆, 且拆完不丢依赖)
     属性: {C,S,T}
     F = { {S,T}->{C} , {T}->{C} }
     候选键: {S,T}     主属性: {S,T}
     {S,T}->{C} : {S,T}+ = {C,S,T}  =>  左边是超键 -> BCNF 直接放行
     {T}->{C} : {T}+ = {C,T}  =>  右边含非主属性 -> 3NF 也违反
     拆 {C,S,T}  依据 {T}->{C}  =>  {C,T}  +  {S,T}
     分解结果: {C,T}  |  {S,T}
     无损连接: 是  ({T} -> {C} 成立(被 F 蕴含); 闭包 {T}+ = {C,T})
     保持依赖: 是

   ● 例 B(教科书反例: BCNF 分解会丢依赖)
     属性: {C,S,T}
     F = { {S,T}->{C} , {C}->{T} }
     候选键: {C,S} | {S,T}     主属性: {C,S,T}
     {S,T}->{C} : {S,T}+ = {C,S,T}  =>  左边是超键 -> BCNF 直接放行
     {C}->{T} : {C}+ = {C,T}  =>  右边全是主属性 -> 3NF 放行, BCNF 不放行
     拆 {C,S,T}  依据 {C}->{T}  =>  {C,T}  +  {C,S}
     分解结果: {C,T}  |  {C,S}
     无损连接: 是  ({C} -> {T} 成立(被 F 蕴含); 闭包 {C}+ = {C,T})
     保持依赖: 否   丢失 {S,T}->{C}

   ★ 判读方法: 例 A 与例 B 的唯一区别是那条非键 FD 的右边是不是主属性。
     同一个 R(S,T,C), 换一种语义就成了'能无损又保依赖'或'只能二选一'。
