## 1. 一句话结论

图 7-11 的实体集 `instructor` **不是一张表**，而是：

| 图中的东西 | 落到哪里 | 依据 |
| --- | --- | --- |
| `ID`、`date_of_birth` | 主表的普通列 | 单值属性 → 一列 |
| `name(first_name, middle_initial, last_name)` | 主表 3 列，`name` 本身不出现 | 复合属性 → 展平成叶子 |
| `address(street(street_number, street_name, apt_number), city, state, zip)` | 主表 6 列，`address`、`street` 都不出现 | 复合属性（可嵌套）→ 逐层展平 |
| `{phone_number}` | **单独一张表** `instructor_phone` | 多值属性 → 独立关系 |
| `age()` | **不建列**，查询时现算或用视图 | 派生属性 → 不存储 |

所以是 **2 张表 + 1 个视图**，不是 1 张宽表。

## 2. 属性对照表（逐项交代，别漏）

| 图 7-11 的属性 | 建表后的列 | 说明 |
| --- | --- | --- |
| `ID` | `er_instructor.ID CHAR(5)` | 主键 |
| `name.first_name` | `first_name VARCHAR(20) NOT NULL` | 展平 |
| `name.middle_initial` | `middle_initial CHAR(1) NULL` | 可以没有中间名 → 允许 NULL |
| `name.last_name` | `last_name VARCHAR(20) NOT NULL` | 展平 |
| `address.street.street_number` | `street_number VARCHAR(10) NULL` | 三层复合展到第二层叶子 |
| `address.street.street_name` | `street_name VARCHAR(30) NULL` | |
| `address.street.apt_number` | `apt_number VARCHAR(10) NULL` | 独栋房子没有公寓号 → NULL |
| `address.city` | `city VARCHAR(20) NULL` | |
| `address.state` | `state VARCHAR(20) NULL` | |
| `address.zip` | `zip CHAR(5) NULL` | 5 位数字，可加 CHECK |
| `{phone_number}` | `er_instructor_phone.phone_number VARCHAR(15)` | 多值 → 另一张表，一行一个号码 |
| `date_of_birth` | `date_of_birth DATE NULL` | 普通属性 |
| `age()` | 无此列 | 派生：`date_of_birth` 算出来 |

多值属性那张表的主键 = **宿主主键 + 属性本身**：`PRIMARY KEY (ID, phone_number)`，
并对 `ID` 建外键指向主表（`ON DELETE CASCADE`）。

## 3. 完整 DDL

### PostgreSQL 17

```sql
CREATE TABLE er_instructor (
    ID              CHAR(5)      NOT NULL,
    first_name      VARCHAR(20)  NOT NULL,
    middle_initial  CHAR(1)          NULL,
    last_name       VARCHAR(20)  NOT NULL,
    street_number   VARCHAR(10)      NULL,
    street_name     VARCHAR(30)      NULL,
    apt_number      VARCHAR(10)      NULL,
    city            VARCHAR(20)      NULL,
    state           VARCHAR(20)      NULL,
    zip             CHAR(5)          NULL,
    date_of_birth   DATE             NULL,
    CONSTRAINT pk_er_instructor     PRIMARY KEY (ID),
    CONSTRAINT ck_er_instructor_zip CHECK (zip IS NULL OR zip ~ '^[0-9]{5}$'),
    CONSTRAINT ck_er_instructor_apt CHECK (apt_number IS NULL OR apt_number ~ '^[0-9]+$')
);

CREATE TABLE er_instructor_phone (
    ID            CHAR(5)      NOT NULL,
    phone_number  VARCHAR(15)  NOT NULL,
    CONSTRAINT pk_er_instructor_phone PRIMARY KEY (ID, phone_number),
    CONSTRAINT fk_er_instructor_phone FOREIGN KEY (ID)
        REFERENCES er_instructor (ID) ON DELETE CASCADE,
    CONSTRAINT ck_er_instructor_phone
        CHECK (phone_number ~ '^[0-9]{3}-[0-9]{3}-[0-9]{4}$')
);
```

### MySQL 8.0

DDL 与上面一一对应，只有三处写法不同：

```sql
    CONSTRAINT ck_er_instructor_zip CHECK (zip IS NULL OR zip REGEXP '^[0-9]{5}$'),
    ...
    CONSTRAINT ck_er_instructor_phone
        CHECK (phone_number REGEXP '^[0-9]{3}-[0-9]{3}-[0-9]{4}$')
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

1. `~` → `REGEXP`；
2. 建表语句末尾加 `ENGINE = InnoDB DEFAULT CHARSET = utf8mb4`（要外键就必须 InnoDB）；
3. CHECK 约束要 MySQL 8.0.16 以上才真正执行（本机 8.0.44 有效，实测 `zip='ABCDE'`、
   `phone_number='abc'` 都被拒绝）。

### 派生属性 age 怎么用

不要建列，查询时现算：

```sql
-- PostgreSQL：age() 直接给出「X 年 X 月 X 天」，取年就是 age
SELECT ID, last_name, EXTRACT(YEAR FROM age(date_of_birth))::int AS age
FROM er_instructor;

-- MySQL：没有 age()，用 TIMESTAMPDIFF
SELECT ID, last_name, TIMESTAMPDIFF(YEAR, date_of_birth, CURDATE()) AS age
FROM er_instructor;
```

要对外看起来就跟图 7-11 那个实体一样，就把「两张表 + 现算」固化成视图：

```sql
CREATE VIEW v_er_instructor_full AS
SELECT i.ID, i.first_name, i.middle_initial, i.last_name,
       i.street_number, i.street_name, i.apt_number, i.city, i.state, i.zip,
       string_agg(p.phone_number, ', ' ORDER BY p.phone_number) AS phone_numbers,
       i.date_of_birth,
       EXTRACT(YEAR FROM age(i.date_of_birth))::int AS age
FROM er_instructor i
LEFT JOIN er_instructor_phone p ON p.ID = i.ID
GROUP BY i.ID, i.first_name, i.middle_initial, i.last_name,
         i.street_number, i.street_name, i.apt_number,
         i.city, i.state, i.zip, i.date_of_birth;
-- MySQL 把 string_agg(...) 换成 GROUP_CONCAT(p.phone_number ORDER BY p.phone_number SEPARATOR ', ')
```

注意必须用 `LEFT JOIN`：多值属性允许取 **0 个值**（示例里 45565 一个电话都没有），
用内连接会把这个人整个弄丢。

### 如果非要存 age：只能存「截至某个固定日期的年龄」

生成列要求表达式不可变／确定性，`age(生日)`（依赖今天）和 `CURDATE()` 都会被拒绝：

- PostgreSQL 实测报错：`生成表达式不是不可变的`（`age(DATE '2026-01-01', date_of_birth)` 同样被拒，它是 stable）；
- MySQL 实测报错：`Expression of generated column 'a' contains a disallowed function: curdate`。

所以只能写成纯算术：

```sql
-- PostgreSQL：2026 − 出生年 − (出生月日 > 1 月 1 日 ? 1 : 0)
ALTER TABLE er_instructor
    ADD COLUMN age_at_2026_01_01 INT
    GENERATED ALWAYS AS (
        2026 - EXTRACT(YEAR FROM date_of_birth)::int
             - CASE WHEN (EXTRACT(MONTH FROM date_of_birth), EXTRACT(DAY FROM date_of_birth))
                         > (1::numeric, 1::numeric)
                    THEN 1 ELSE 0 END
    ) STORED;

-- MySQL：固定基准日期常量是可以的
ALTER TABLE er_instructor
    ADD COLUMN age_at_2026_01_01 INT
    GENERATED ALWAYS AS (TIMESTAMPDIFF(YEAR, date_of_birth, '2026-01-01')) STORED;
```

## 4. 反例：把 `{phone_number}` 塞进一列会怎样

```sql
CREATE TABLE er_instructor_bad (
    ID CHAR(5) PRIMARY KEY,
    last_name VARCHAR(20),
    phone_number VARCHAR(50)   -- '608-555-1234, 608-555-9876'
);
```

脚本里实测了后果：

1. **精确查找查不到**：`WHERE phone_number = '608-555-1234'` → 0 行，号码被埋在一串字符里；
2. **只能 LIKE，于是误命中**：`WHERE phone_number LIKE '%608-555-1234%'` → 2 行，
   其中 45565 的号码其实是 `608-555-12340`，被当成了同一个号；
3. **没法约束单个号码**：格式 CHECK、唯一性都只能加在整列上，多值无从谈起；
4. **统计困难**：想数「有几个人有两个电话」得写字符串函数。

结论：多值属性违反第一范式的原子性要求，必须单独建表 —— 这正是图 7-11 画花括号 `{}` 的原因。

## 5. 易错点清单

1. **给 `name`、`address` 也建列**：教材做法是只留叶子，`name`、`address`、`street` 都不作列出现。
2. **给多值属性建「电话 1、电话 2、电话 3」三列**：电话个数不定，加第四个又要改表结构，本质还是非原子。
3. **用 `phone_number` 单列作主键**：两个人可能共用号码（示例里 22222 与 83821 就是），必须用 `(ID, phone_number)`。
4. **派生属性也存一列**：`age` 每年都要批量更新，一旦忘记更新就和 `date_of_birth` 打架；能算就别存。
5. **拼回实体时用 INNER JOIN**：多值属性取 0 个值时会把整个实体丢掉。
6. **忘记 `ON DELETE CASCADE`**：删教师时留下孤儿电话行，破坏参照完整性。

## 6. 自测

**题 1** 图 7-11 的 `address` 展开后有哪几列？为什么 `address` 本身不建列？
**题 2** `{phone_number}` 为什么不能放进 `instructor` 表？那张新表的主键应该是什么？
**题 3** `age()` 是派生属性，能不能建成 `age INT` 一列？如果一定要存，要注意什么？

**答案**
1. `street_number, street_name, apt_number, city, state, zip` 六列；复合属性只保留叶子，中间层（`address`、`street`）只是分组，不是数据。
2. 因为一个教师可以有多个电话，塞进一列就违反原子性（无法约束、无法精确查询）；新表主键为 `(ID, phone_number)`，`ID` 为外键。
3. 不该建，应该现算或放视图；确实要存时必须固定基准日期（生成列不接受 `CURRENT_DATE` / `CURDATE()`），并且要接受「存下来的值会过期」。
