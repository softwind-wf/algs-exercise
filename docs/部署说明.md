# 部署说明（University Website）

本项目位于 algs4 根工程下，是一个 Spring Boot 2.7（Java 8）+ Spring MVC + MyBatis + Thymeleaf + Bootstrap 的大学网站，业务包为 `com.ds.university`。

## 1. 环境要求

- JDK 8+、Maven、MySQL 8（本地 `university` 库）
- **Redis 5+**（多实例共享状态：在线统计 / 登录限流 / 聊天跨实例路由；默认 `localhost:6379`，可用 `REDIS_HOST`/`REDIS_PORT` 覆盖。Windows 可用 Redis-x64 MSI 安装为系统服务；单实例部署可将 `MULTI_INSTANCE_ENABLED` 设为 `false` 退回内存实现）

| 软件 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 1.8+ | 项目 `pom.xml` 配置 `java.version=1.8`，请勿使用 JDK 17+ 直接运行 Spring Boot 2.7 |
| Maven | 3.6+ | 构建与依赖管理 |
| MySQL | 8.0 | 业务库 `university`（含示例数据 + 账号权限表） |
| IDE | IntelliJ IDEA 等 | 直接运行 `UniversityApplication` |

## 2. 数据库初始化与升级（Flyway 自动迁移）

schema 由 **Flyway** 版本化管理，应用启动时自动迁移，**禁止手工改库**。

迁移脚本位于 `src/main/resources/db/migration/`：

| 脚本 | 作用 |
| --- | --- |
| `V1__business_schema_and_data.sql` | 11 张业务表 + 示例数据 |
| `V2__auth_rbac_schema_and_data.sql` | 5 张 `sys_*` 账号/角色/权限表 + 演示账号 |
| `V3__audit_log.sql` | 审计日志表 `audit_log` |
| `V4__instructor_phone_number.sql` | 收编存量库手工加的 `instructor.phone_number` 列（幂等 ALTER） |

脚本均为幂等写法（`CREATE TABLE IF NOT EXISTS` + `INSERT IGNORE`），不 DROP 任何对象；应用记录在 `flyway_schema_history` 表，并通过 `validate-on-migrate` 校验已应用脚本未被篡改。

### 全新环境

只需创建空库，然后正常启动应用，Flyway 自动建表灌数：

```sql
CREATE DATABASE university DEFAULT CHARACTER SET utf8mb4;
```

### 存量库（已由旧版手工 SQL 建好）

直接升级部署即可。配置了 `baseline-on-migrate: true` + `baseline-version: 0`：首次启动自动打基线，随后 V1~V3 依次重放——表已存在则跳过建表、数据已存在则跳过插入，不会破坏线上数据（演示账号用 `INSERT IGNORE`，不会冲掉已修改的密码）。

### 后续版本升级

新增 schema 变更时，**新增**一个 `V5__xxx.sql`（版本号递增，脚本一旦发布禁止修改），随应用上线自动应用。无需任何人手工执行 SQL。

### 从零重建演示库（可选）

仅当需要彻底清空重来时使用手工脚本（开头含 `DROP DATABASE`，会清空所有数据）：

```bash
mvn -q compile
java -cp "target/classes;target/cp.txt" com.ds.db.UniversityDbSetup
```

> 若 `target/cp.txt` 不存在，先执行
> `mvn -q org.apache.maven.plugins:maven-dependency-plugin:3.6.1:build-classpath -Dmdep.outputFile=target\cp.txt`

也可用 `sql.bat -f src\main\resources\sql\university.sql` 或 MySQL 客户端手工执行这两个脚本。重建后启动应用，Flyway 会自动打基线并幂等补齐迁移记录。

## 3. 应用配置

`src/main/resources/application.yml` 中数据源默认：

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/university?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${DB_USER:root}
    password: ${DB_PASSWORD:root}
```

- 端口默认 `8080`，可用环境变量或命令行覆盖：`--server.port=8081`。
- 账号密码可用环境变量 `DB_USER` / `DB_PASSWORD` 覆盖，不必改文件。
- 头像上传目录默认 `./uploads/avatars`（应用启动目录下，可用环境变量 `APP_UPLOAD_DIR` 覆盖）；头像文件存于该目录，数据库 `sys_user.avatar` 仅存文件名，通过 `/uploads/avatars/{文件名}` 访问。
- 开发期已开启 `thymeleaf.cache=false` 与 `spring-boot-devtools`（改代码自动重启）。

## 4. 启动应用

方式一：IDE（推荐）

1. 用 IntelliJ IDEA 打开 algs4 根目录（pom.xml 已被识别为 Spring Boot 工程）。
2. 运行主类 `com.ds.university.UniversityApplication`。
3. 浏览器访问 <http://localhost:8080/>。

方式二：Maven 命令行

```bash
mvn spring-boot:run
```

方式三：打包后运行

```bash
mvn clean package -DskipTests
java -jar target/algs4-1.0.0.0.jar
```

> 打包会包含前端静态资源（Bootstrap、调度看板 JS 等），jar 可独立部署。

## 5.1 HTTPS（TLS）部署

应用内置内嵌 Tomcat 的 TLS 支持，提供独立 `tls` profile：

1. 生成自签名证书（一次性）：`powershell -ExecutionPolicy Bypass -File scripts\gen-keystore.ps1`（输出 `keystore/university.p12`，密码 `changeit`，有效期 10 年，SAN 含 localhost/127.0.0.1）
2. 以 `tls` profile 启动：
   ```bash
   java -jar target/algs4-1.0.0.0.jar --spring.profiles.active=dev,tls
   ```
   （IDEA 中在 Run Configuration 的 Program arguments 加 `--spring.profiles.active=dev,tls`）
3. 访问 <https://localhost:8443>（默认 HTTP 8080 不受影响）

生产环境注意：

- 自签名证书仅供开发/演示，正式环境请用正式证书（可用环境变量 `KEYSTORE_PATH` / `KEYSTORE_PASSWORD` / `KEYSTORE_ALIAS` 指向外部证书，或由 nginx/caddy 反向代理终结 TLS，应用保持 HTTP）
- 聊天 WebSocket 会自动跟随协议：HTTPS 页面下走 `wss://`（前端已按 `location.protocol` 自动切换）

## 7. 运维（健康检查 / 监控告警 / Docker 部署 / CI）

### 7.1 健康检查与运行指标（Actuator）

应用内置 Spring Boot Actuator，只暴露三个端点（`application.yml` 的 `management` 配置块），敏感端点（env/beans 等）默认关闭：

| 端点 | 用途 |
| --- | --- |
| `/actuator/health` | 整体健康（含 DB 连通性、磁盘空间明细），K8s/负载均衡探活可直接用 |
| `/actuator/health/liveness`、`/actuator/health/readiness` | K8s 存活/就绪探针（`probes.enabled: true` 已开启） |
| `/actuator/prometheus` | Prometheus 格式运行指标（JVM 内存、HTTP 请求量/耗时分布等） |

验证方式：`curl http://localhost:8080/actuator/health`，正常返回 `{"status":"UP",...}`。

> 注意：重启部署时先确认旧进程已退出再启动新 jar，否则新实例会因 8080 端口被旧进程占用而启动失败，探活仍打到旧版本上。

### 7.2 Docker 一键部署

仓库根目录提供多阶段 `Dockerfile`（maven 构建 → temurin 8-jre 运行，含 curl HEALTHCHECK）与 `docker-compose.yml`（app + MySQL 8.0 + Prometheus + Alertmanager 四服务）：

```bash
docker compose up -d --build
```

- 首次启动由 MySQL 容器自动建 `university` 空库，应用启动时 Flyway 自动建表灌数，无需手工初始化。
- 访问入口：应用 <http://localhost:8080/>、Prometheus <http://localhost:9090/>、Alertmanager <http://localhost:9093/>。
- 数据库凭据通过 compose 环境变量（`DB_USER`/`DB_PASSWORD`）覆盖，生产环境请改为外部注入密钥，勿沿用默认 root。
- MySQL 数据卷 `mysql-data` 持久化，`docker compose down` 不丢数据；`down -v` 才会清库。
- 头像上传目录通过 `uploads-data` 命名卷挂载到容器 `/app/uploads`，升级/重建容器不丢用户头像。

### 7.3 监控告警（Prometheus + Alertmanager）

配置位于 `docker/` 目录，随 compose 挂载：

| 文件 | 作用 |
| --- | --- |
| `docker/prometheus.yml` | 抓取 `app:8080/actuator/prometheus`，关联告警规则与 Alertmanager |
| `docker/alert-rules.yml` | 4 条告警规则（见下） |
| `docker/alertmanager.yml` | 告警路由骨架，通知渠道为占位，接入钉钉/企微时在此配置 webhook |

内置告警规则：

| 规则 | 触发条件 | 级别 |
| --- | --- | --- |
| UniversityAppDown | 应用抓取失败持续 1 分钟 | critical |
| UniversityHighErrorRate | 5xx 占比超过 5% 持续 5 分钟 | warning |
| UniversityHighLatency | 请求 p95 延迟超过 2s 持续 5 分钟 | warning |
| UniversityJvmMemoryPressure | 堆内存使用率超过 90% 持续 5 分钟 | warning |

### 7.4 CI（GitHub Actions）

工作流 `.github/workflows/ci.yml`，push/PR 到 `main` 自动触发：

1. **test**：启动 mysql:8.0 服务容器（空库，Flyway 自动迁移），JDK 8 下 `mvn -B clean test` 全量测试，失败时上传 surefire 报告。
2. **docker-build**：仅 main 分支 push 触发，buildx 构建镜像验证 Dockerfile 可构建（不推送镜像仓库）。

发布流程：合入 main → CI 全绿 → 构建镜像/打包 jar → 部署。替代此前纯手工发布。

### 7.5 备份与恢复预案

成绩、选课等核心数据全部在 `university` 库（成绩在 `takes` 表），丢数据属于重大事故，必须有可执行的备份与恢复手段。

**备份策略**

| 项 | 取值 |
| --- | --- |
| 备份范围 | 整个 `university` 库（全部表结构 + 数据 + `flyway_schema_history`） |
| 方式 | `mysqldump --single-transaction`，InnoDB 一致性快照，不锁表不阻塞业务 |
| 频率 | 每日一次（建议凌晨低峰，见下方定时任务） |
| 保留 | 默认最近 14 份，`-Keep` 可调 |
| 完整性校验 | 退出码 + `Dump completed on` 标记 + 文件大小，任一不通过则删除坏文件并记 FAILED |
| 日志 | `backups\backup.log`，每次记录行数快照（takes/student/instructor），恢复后可比对 |

**脚本（`scripts/` 目录，凭据读 `db.properties`，无此文件时回退 `DB_USER`/`DB_PASSWORD` 环境变量）**

```powershell
# 备份（默认输出到 backups\，自动校验+轮转）
powershell -ExecutionPolicy Bypass -File scripts\backup-university-db.ps1
# 可选：指定目录与保留份数（生产建议指向另一块盘/网络位置）
powershell -ExecutionPolicy Bypass -File scripts\backup-university-db.ps1 -BackupDir D:\db-backup -Keep 30

# 恢复（默认选最新 dump；交互需键入库名确认，-Force 跳过；恢复前自动先做一次安全备份）
powershell -ExecutionPolicy Bypass -File scripts\restore-university-db.ps1
powershell -ExecutionPolicy Bypass -File scripts\restore-university-db.ps1 -DumpFile backups\university_20260811_020000.sql
```

**定时备份（Windows 任务计划，每天凌晨 2 点）**

```bat
schtasks /Create /SC DAILY /ST 02:00 /TN UniversityDbBackup /TR "powershell -NoProfile -ExecutionPolicy Bypass -File D:\downloads\algs4-master\algs4-master\scripts\backup-university-db.ps1"
```

**数据丢失应急恢复 SOP**

1. 停止应用（避免恢复期间继续写入）。
2. 运行 `restore-university-db.ps1`（脚本会先对当前现场做一次安全备份，再 DROP 重建全部表并导入 dump）。
3. 核对脚本输出的行数校验（takes/student/instructor/flyway_history）与 `backup.log` 中事故前最后一次 BACKUP OK 的快照是否一致。
4. 重启应用，确认 `/actuator/health` 为 UP（Flyway 历史表随 dump 一起恢复，不会重跑迁移）。

**Docker 部署的备份**：对 compose 里的 MySQL 容器执行
`docker compose exec -T mysql mysqldump -uroot -p$DB_PASSWORD --single-transaction --databases university > backup.sql`，
恢复同理 `docker compose exec -T mysql mysql -uroot -p$DB_PASSWORD < backup.sql`。

**约定**：生产环境备份目录不要与应用同一块盘；重大操作（升级、迁移、清数据）前必须先手工备份一份；备份文件含全量数据（含账号哈希），注意访问权限。已实际演练验证：备份 → 恢复 → 行数一致 → 集成测试全绿。

## 8. 常见问题

| 问题 | 处理 |
| --- | --- |
| 8080 端口被占用 | 改用 `--server.port=8081` 启动，或先关闭占用进程；发布时特别注意旧 jar 进程未退出会导致新实例启动失败、健康检查仍打到旧版本 |
| 登录提示数据库错误 | 确认 `university` 库已创建，`application.yml` 数据源账号密码正确；查看启动日志中 Flyway 迁移是否报错 |
| Flyway 校验失败（Validate failed） | 说明已应用的迁移脚本被改动过。恢复脚本原样；确需调整时只能新增下一个版本脚本（如 `V5__xxx.sql`），不要修改历史脚本 |
| `flyway_schema_history` 是什么 | Flyway 的迁移历史表，记录每个版本脚本的应用时间与校验和，勿手工增删改 |
| 迁移失败了一半怎么办 | 修复脚本问题后重启应用即可续跑；失败记录可用 Flyway `repair`（或删掉该失败行）清理后重试 |
| 中文乱码 | 连接串已带 `characterEncoding=UTF-8`，数据库字符集为 `utf8mb4`；控制台乱码可加 `-Dfile.encoding=UTF-8` |
| 修改代码不生效 | 开发期已引入 `spring-boot-devtools`，改类后自动重启；若未生效检查 IDE 是否开启了自动构建 |
| 需要临时验证页面 | 用 `scripts/start-test-app.ps1 -Port 8081` 启动 8081 实例，验证完删除 `target/app8081*` 与 `target/cp.txt` |
