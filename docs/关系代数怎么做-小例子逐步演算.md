# 关系代数怎么做：用 5 行小表把每一步演出来

> 配套脚本：`src/main/resources/sql/ra_walkthrough.sql`
> 跑法：`.\psql.bat -f src\main\resources\sql\ra_walkthrough.sql`
> 　　　`.\sql.bat -db university -f src\main\resources\sql\ra_walkthrough.sql`（MySQL）
> 本文所有表格都是脚本实跑输出（PostgreSQL 17.11 与 MySQL 8.0.44 各跑一遍，0 报错，跑完自动删表）。

## 0. 为什么「看得懂、下不了手」

《数据库系统概念》第 6 章讲关系代数的写法是：**给一个表达式 + 一句结论**，中间的每一步关系全部省略。
再加上书里用 `instructor`（十几行）举例，笛卡尔积一两百行，根本没法手算 —— 于是「表达式为什么长这样」就断了。

所以这里把表故意做小（5 行），每一步的中间结果都打印出来，你可以当场数行数、对答案。

## 1. 拿到任何一道题，先走这五步

| 步骤 | 问自己 | 落到运算上 |
|---|---|---|
| 1 | 结果要**哪几列**？ | 最外层 `π`（投影列表） |
| 2 | 数据在**哪几张表**？ | 一张表够 → 单表；要两表信息 → `×` 或 `⋈` |
| 3 | 条件是什么**类型**？ | 单行条件（工资>80000）→ `σ`；<br>跨行比较（最高、至少、**全部**）→ 自连接 + `ρ` + 差集，或 `NOT EXISTS`；<br>两表按公共属性对接 → `⋈` |
| 4 | 从里往外写表达式，再翻成 SQL | 见第 3 节的翻译对照 |
| 5 | 怎么知道写对了？ | 数行数 → 看极值 → 和 `MAX` / `COUNT` 的写法对照 |

## 2. 每个运算的「输入 → 输出」（真实结果）

底表 `ins`（只有 5 行，这就是全部数据）：

| ID | name | dept_name | salary |
|---|---|---|---|
| 10101 | Alice | Comp. Sci. | 60000.00 |
| 22222 | Bob | Physics | 90000.00 |
| 33456 | Carol | Physics | 70000.00 |
| 45565 | Dave | Comp. Sci. | 95000.00 |
| 58583 | Erin | History | 95000.00 |

### 2.1 选择 σ —— 挑「行」

`σ_dept_name = Physics (ins)` → 5 行里只剩 2 行：

| ID | name | salary |
|---|---|---|
| 22222 | Bob | 90000.00 |
| 33456 | Carol | 70000.00 |

### 2.2 投影 π —— 挑「列」，并且**自动去重**

`π_name,salary(ins)` → 5 行（只是少了 `ID`、`dept_name` 两列）。

`π_salary(ins)` → **只有 4 行**：两个 95000 合成一个。

| salary |
|---|
| 95000.00 |
| 90000.00 |
| 70000.00 |
| 60000.00 |

而 SQL 不写 `DISTINCT` 会返回 5 行（95000 出现两次）。**关系是集合，不允许重复元组** —— 这是最常对不上的地方。

### 2.3 笛卡尔积 × —— 行两两拼接

`ins × ins` → 5 × 5 = **25 行**。列名要靠限定名区分：`ins.salary` 和 `d.salary`。
正因为两个 `salary` 同名，才需要下一步的更名运算 `ρ`。

### 2.4 更名 ρ + 选择 σ —— 书里「找出最高工资」的第一步

`ρ_d(ins)` 把副本改名成 `d`，于是能写 `σ_ins.salary < d.salary`：
含义是「**保留工资比别人低的那个我**」，也就是「我不是最高工资」。

`σ_{ins.salary < d.salary}(ins × ρ_d(ins))` → 25 行里剩 9 行：

| i_id | i_name | i_salary | d_id | d_name | d_salary |
|---|---|---|---|---|---|
| 22222 | Bob | 90000.00 | 45565 | Dave | 95000.00 |
| 22222 | Bob | 90000.00 | 58583 | Erin | 95000.00 |
| 33456 | Carol | 70000.00 | 22222 | Bob | 90000.00 |
| 33456 | Carol | 70000.00 | 58583 | Erin | 95000.00 |
| 33456 | Carol | 70000.00 | 45565 | Dave | 95000.00 |
| 10101 | Alice | 60000.00 | 33456 | Carol | 70000.00 |
| 10101 | Alice | 60000.00 | 22222 | Bob | 90000.00 |
| 10101 | Alice | 60000.00 | 45565 | Dave | 95000.00 |
| 10101 | Alice | 60000.00 | 58583 | Erin | 95000.00 |

数一下就能验证：60000 比 4 个人低、70000 比 3 个人低、90000 比 2 个人低、95000 不比任何人低 → 4+3+2 = 9 行，对上了。

### 2.5 集合差 − —— 第二步：全部工资 减去 上面的「不是最高」

`π_salary(ins) − π_salary(上一步)` → 只剩 **95000**。

要「换回人」，用 `NOT EXISTS`（不存在工资比我高的人）：结果是 **Dave 和 Erin 两个人**（并列最高要全部列出；而差集只会给出一个值）。

### 2.6 连接 ⋈ —— 两张表按公共属性对接

`ins ⋈ dept`（按 `dept_name`）→ 5 行，每行配上自己系的楼；再 `σ_building=Watson` + `π_name` → **Bob、Carol**。

## 3. 书上一句带过、但考试/作业会考的三种写法

### 3.1 广义投影：投影列表里放「表达式」

`π_{ID, name, salary*1.1}(ins)` —— 投影的同时逐行计算：

| ID | name | old_salary | new_salary | raise |
|---|---|---|---|---|
| 45565 | Dave | 95000.00 | 104500.00 | 9500.00 |
| 58583 | Erin | 95000.00 | 104500.00 | 9500.00 |
| 22222 | Bob | 90000.00 | 99000.00 | 9000.00 |
| 33456 | Carol | 70000.00 | 77000.00 | 7000.00 |
| 10101 | Alice | 60000.00 | 66000.00 | 6000.00 |

SQL 的对应物就是 `SELECT` 列表里的表达式（算术、常量、`CASE`、函数）。

### 3.2 位置标记 `$i`：用「第几位」代替属性名

本表次序：`$1=ID`、`$2=name`、`$3=dept_name`、`$4=salary`。
`ins × ins` 之后第二个 `ins` 的 salary 排到第 8 位，所以书里写：

```
Π_$4(ins) − Π_$4( σ_$4 < $8 ( ins × ins ) )    =  95000
```

位置天然把两个 salary 分开了（第 4 位 vs 第 8 位），所以**用位置标记时更名运算 ρ 可以省掉**。
SQL 没有 `$i` 写法（只有 `ORDER BY` / `GROUP BY` 收序号），用 CTE 的列名清单按位置改名来模拟：
`WITH r (c1,c2,c3,c4) AS (SELECT ID,name,dept_name,salary FROM ins)` —— 此后 `c4` 就是 `$4`。

### 3.3 除运算：「全部 / 所有」→ 双重否定

题：**选修了 Biology 全部课程的学生**。
手算思路：这个学生「**不存在**一门 Biology 课是他「**没选**」的」。两层 `NOT EXISTS` 就是除法的 SQL 写法：

```
π_ID( takes ) ÷ π_course_id( σ_dept=Biology(course) )
```

结果：**10101、33456**（Alice 和 Carol）。
另一种写法是「数够门数」：`GROUP BY ID HAVING COUNT(DISTINCT course_id) = (Biology 课程总数)`，结果相同。

## 4. 易错点清单

1. **π 会去重**，SQL 要显式 `DISTINCT` 才等价（第 2.2 节）。
2. **自连接必须更名**，否则两个同名属性分不清；`ρ_d(E)` 在 SQL 里就是 `FROM E AS d`。
3. **「全部 / 所有 / 每个」= 双重 `NOT EXISTS`**（∀ 转成 ¬∃¬），不是 `COUNT` 一拍脑袋。
4. **差集 / 并 / 交要求「同元」**：属性个数、对应域都要相容，否则表达式根本不合法。
5. **并列要当心**：差集只回一个值，`NOT EXISTS` / `IN` 会把并列的人全列出来。
6. **位置标记只是在省事**，语义与属性名写法完全等价；书上 `instructor` 是 4 个属性所以写 `$4<$8`，本项目库里多一列 `phone_number`，所以是 `$4<$9`。

## 5. 自测 3 题（答案已在脚本第 11 节跑出来）

| # | 题目 | 参考思路 | 答案 |
|---|---|---|---|
| 1 | 找出 Physics 系工资最高的教师姓名 | `σ_dept=Physics` + `NOT EXISTS`（同系没有更高的人） | Bob |
| 2 | 找出没有选 CS-101 的学生 | `π_ID(takes) − π_ID(σ_course=CS-101(takes))` | 22222、33456 |
| 3 | 找出与 Carol 同系但工资比她高的教师 | 先取 Carol 的系与工资，再在同系里比 | Bob |

**思考题**：找出工资高于本系平均工资的教师。
基本关系代数（σ π × − ∪ ∩ ⋈）**写不出来** —— 它要算「平均值」，属于教材后面的**聚集运算**。
SQL 里用相关子查询即可：Dave（系均 77500）、Bob（系均 80000）。
