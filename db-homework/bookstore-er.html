实践习题 7.20 · 网上书店的 E-R 建模

题目：考虑图 7-29 中的 E-R 图，它对一家网上书店建模。
a. 列出实体集及其主码。
b. 假设书店向其展览的商品中增加了蓝光光盘和可下载视频。相同的商品可能在一种格式中存在，或在两种格式中都存在且具有不同的价格。 扩展 E-R 图来为这个新增需求建模，忽略对购物篮的影响。
c. 现在用概化来扩展 E-R 图，从而对包含书、蓝光光盘或可下载视频的任意组合的购物篮进行建模。

图 B · 题 b：新增蓝光光盘与可下载视频（不概化）

图 B：用 product 实体把“同一种商品的不同格式”聚合起来。

建模思路：蓝光光盘与可下载视频各自成为实体集（各有自己的码与价格）；由于同一商品可能只有一种格式、也可能两种格式都有且价格不同， 价格不能放在公共实体上，于是新增 product（product_id, title, year）表示“商品本身”，三种格式各自通过一个 1 : 0..1 的联系 （book_of / blu_ray_of / video_of）挂到 product 上。一个 product 最多有一条 book 记录、一条蓝光记录、一条视频记录，但可以同时有多条。

题 b 要求“忽略对购物篮的影响”，因此此处 contains、stocks（以及 book 上的 written_by / published_by）都保持原样只连 book—— 这正是题 c 要用概化解决的别扭之处：购物篮没法同时装“书 / 蓝光 / 视频”这三种彼此独立的东西。

图 C · 题 c：用概化统一三种商品格式

图 C：product 作为超类，book / blu_ray / downloadable_video 作为子类，contains 与 stocks 挂到超类上。

两个关键约束（答题时要写出来）：

  • 全概化 total：每个商品至少属于一种格式，不存在“什么格式都不是”的商品（图 B 里就能插入这样的脏数据，概化后由超类-子类结构 + 约束挡住）。
  • 重叠 overlapping：同一商品可以同时是蓝光光盘和可下载视频（两个格式、两个价格）。不能用“单表 + 判别列 + CHECK”的方式落地—— 那只能表达不相交；必须用“超类表 + 各子类表”的方案。

概化带来的三个变化：① contains（购物篮 M:N）与 stocks（仓库 M:N）改挂到超类 product，于是购物篮可以装任意组合； ② price 下沉到三个子类（同一商品两种格式 = 两条子类记录、两个价格）；③ product 上的 title / year 保留在超类（各格式共用）。 另外落地时还要补一刀：当同一商品有两种格式时，“篮里买的到底是哪一种”光靠 product 表达不出来， 所以给 contains 再加一个联系属性 format（取值 book / blu_ray / downloadable_video），SQL 里并用触发器保证这个格式对该商品确实存在。

表 C-1　概化后的关系模式（最终设计）

author (name, address, url)                            -- 主码 name
publisher (name, address, phone, url)                  -- 主码 name
customer (email, name, address, phone)                 -- 主码 email
shopping_basket (basket_id, email)                     -- 主码 basket_id, 外键 email → customer(1:N 并入 N 端)
warehouse (code, address, phone)                       -- 主码 code

product (product_id, title, year)                      -- 主码 product_id   ← 概化的超类
book (ISBN, product_id, price)                         -- 主码 ISBN, 外键 product_id → product(UNIQUE)
blu_ray (upc, product_id, price)                       -- 主码 upc,  外键 product_id → product(UNIQUE)
downloadable_video (video_id, product_id, price, duration_min)
                                                       -- 主码 video_id, 外键 product_id → product(UNIQUE)

written_by (name, ISBN)                                -- M:N, 主码 (name, ISBN)
published_by → book.pub_name                           -- 1:N, 把 publisher 主码并入 book

contains (basket_id, product_id, number, format)       -- M:N, 主码 (basket_id, product_id, format)
                                                       -- 联系属性 number(数量)、format(买的是哪种格式)
stocks (code, product_id, number)                      -- M:N, 主码 (code, product_id), 联系属性 number

约束：product_id 在三个子类表里各建 UNIQUE（一个商品每种格式最多一条）；全概化用可延迟约束触发器保证（见 SQL 脚本步骤 6）。

题 b 的另一种写法（考场可两句话交代）

若不想引入 product 实体，也可以只把蓝光/视频建成两个实体集，并用一个“同一作品”联系把 Blu-ray 与可下载视频连起来（M:N）。 这种写法只能表达这两种格式之间的对应，书无法参与，而且购物篮仍然只能装书 —— 所以题 c 才要求用概化：把三种格式统一成 product 的子类。
