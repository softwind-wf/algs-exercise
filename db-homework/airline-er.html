实践习题 7.23 · 航空公司数据库设计

题目：为航空公司设计一个数据库。数据库必须追踪客户和他们的预订、航班、他们在航班上的状态、座位分配， 以及未来航班的时刻表和飞行路线。
要求：设计应包括 E-R 图、关系模式的集合，以及包括主码约束和外码约束的一组约束。

二、关系模式的集合

customer   (customer_id, name, phone, email, address)                 -- PK customer_id；UNIQUE(email)
airport    (airport_code, airport_name, city, country)               -- PK airport_code
aircraft_type (type_code, manufacturer, model, seat_capacity)        -- PK type_code；CHECK seat_capacity>0
airplane   (reg_no, type_code, delivery_date, status)                -- PK reg_no；FK type_code→aircraft_type
route      (route_no, route_name)                                    -- PK route_no
route_leg  (route_no, leg_no, from_code, to_code, distance_km)       -- PK(route_no, leg_no)  ← 弱实体
                                                                     -- FK route_no→route
                                                                     -- FK from_code / to_code→airport
timetable  (schedule_id, flight_no, route_no, type_code,             -- PK schedule_id
            day_of_week, dep_time, arr_time, valid_from, valid_to)   -- UNIQUE(flight_no, day_of_week, valid_from)
                                                                     -- FK route_no→route, type_code→aircraft_type
flight     (flight_no, flight_date, schedule_id, reg_no,             -- PK(flight_no, flight_date)
            dep_time, arr_time, flight_status)                       -- FK schedule_id→timetable, reg_no→airplane
booking    (booking_id, customer_id, booking_date,                   -- PK booking_id
            total_amount, booking_status)                            -- FK customer_id→customer
booking_segment (booking_id, seg_no, flight_no, flight_date,         -- PK(booking_id, seg_no)  ← 弱实体
                 cabin_class, seat_no, segment_status)               -- FK booking_id→booking
                                                                     -- FK (flight_no, flight_date)→flight

映射规则：1:N 联系把 1 端主码并入 N 端（airplane.type_code、flight.schedule_id/reg_no、timetable.route_no/type_code、 booking.customer_id、route_leg.route_no/from_code/to_code）；弱实体的主码 = 标识联系另一端的主码 + 部分键 （route_leg = route_no + leg_no；booking_segment = booking_id + seg_no）；booking_segment 上的复合外码 (flight_no, flight_date) 就是"订座 ↔ 航班"这个 M:N 联系的落地形式。

表 5　语义约束（CHECK、唯一索引与触发器）

约束内容与实现
基本量seat_capacity > 0、distance_km > 0、total_amount >= 0
枚举cabin_class ∈ (经济舱, 公务舱, 头等舱)；flight_status ∈ (计划, 延误, 已起飞, 已到达, 取消)；booking_status / segment_status ∈ (已确认, 候补, 已登机, 已取消)
时刻表day_of_week BETWEEN 1 AND 7、dep_time < arr_time、valid_from < valid_to
航段from_code <> to_code（一个航段不能同场起降）
座位号seat_no ~ '^[0-9]{1,2}[A-K]$'（如 12A、3C）
座位不被重复占用部分唯一索引：UNIQUE (flight_no, flight_date, seat_no) WHERE seat_no IS NOT NULL AND segment_status <> '已取消' —— 取消的订座自动让出座位
航班与时刻表对齐触发器：具体航班的 flight_no 必须与它引用的时刻表一致；flight_date 的星期必须等于时刻表的 day_of_week；且日期落在 valid_from ~ valid_to 内
座位不超出机型容量触发器：座位排号 × 6 不得超过该航班执飞飞机的机型座位数（跨 booking_segment → flight → airplane → aircraft_type 四张表）
状态与座位自洽触发器：已确认 / 已登机 必须有座位号；候补可以没有座位号
航线航段首尾相接可延迟约束触发器：同一条航线内 leg_no 必须从 1 连续编号，且第 k 段的到达机场 = 第 k+1 段的出发机场
三个设计要点：
① 机票分三层，别混成一张表：timetable（时刻表：班期 + 起降时刻 + 有效期，回答"未来航班怎么排"）→ flight（具体航班：航班号 + 日期，回答"哪一天飞的那一班"）→ booking_segment（某人某航班的座位与状态）。 没有中间层就表达不了"同一航班号不同日期"和"时刻表改了不影响已排航班"。
② 座位分配与乘机状态放在订座航段上：一条订座记录 = 一次订票的一段行程，"已确认 / 候补 / 已登机 / 已取消"+座位号都是它的属性； 联程票就是同一 booking 下多条 segment。
③ 座位冲突交给部分唯一索引：UNIQUE(flight_no, flight_date, seat_no) WHERE segment_status <> '已取消' —— 既保证"一个座位只卖给一个未取消的订座"，又不会因为存在取消记录而挡住建新单（这是普通唯一约束做不到的；示例数据里 5A 座位被取消后又被别人买走）。
