实践习题 7.22 · 全球快递公司数据库设计

题目：为全球性的快递公司（例如 DHL 或 FedEx）设计一个数据库。数据库必须能够追踪寄件的客户和收件的客户； 有些客户可能两者都是。由于每个包裹必须是可标识且可追踪的，因此数据库必须能够存储包裹的位置信息以及它的历史位置。 位置包括卡车、飞机、机场和仓库。
要求：设计应包括 E-R 图、关系模式的集合，以及包括主码约束和外码约束的一组约束。

二、关系模式的集合

customer (customer_id, name, phone, email, address)                 -- 主码 customer_id；UNIQUE(email)
service  (service_code, service_name, sla_days)                     -- 主码 service_code
package  (tracking_no, sender_id, receiver_id, service_code,
          weight_kg, length_cm, width_cm, height_cm,
          declared_value, created_at, status)                       -- 主码 tracking_no
                                                                    -- 外码 sender_id, receiver_id → customer
                                                                    -- 外码 service_code → service
location (location_id, location_name)                               -- 主码 location_id（概化超类）
truck    (location_id, plate_no, capacity_kg)                       -- 主码 location_id 且外码 → location
plane    (location_id, tail_no, model, capacity_kg)                 -- 主码 location_id 且外码 → location
airport  (location_id, iata_code, city)                             -- 主码 location_id 且外码 → location
warehouse(location_id, wh_code, city, capacity_m3)                  -- 主码 location_id 且外码 → location
package_event (tracking_no, event_seq, event_time, location_id, event_type, note)
                                                                    -- 主码 (tracking_no, event_seq)  ← 弱实体
                                                                    -- 外码 tracking_no → package, location_id → location

映射规则：1:N 联系把 1 端主码并入 N 端（package 里塞两个外码分别表示寄件人/收件人， package_event 里塞 location_id）；弱实体的主码 = 标识联系另一端的主码 + 部分键（tracking_no + event_seq）； 概化按"超类表 + 子类表，子类主码同时是外码"落地。

表 5　语义约束（CHECK 与触发器）

约束内容与实现
包裹基本量weight_kg > 0、三边尺寸 > 0、declared_value >= 0
包裹状态CHECK (status IN ('已收寄','运输中','派送中','已签收','异常'))
事件序号/类型event_seq >= 1；CHECK (event_type IN ('收寄','入库','出库','装机','卸机','装车','派送','签收','异常'))
服务时限sla_days > 0
位置概化触发器：每个 location 恰好有一张子类行 —— 0 行报"全概化被破坏"，≥2 行报"不相交被破坏"（一个函数 + 5 枚可延迟约束触发器）
事件不得早于收寄触发器：event_time >= package.created_at（跨表，CHECK 写不出来）
轨迹单调触发器：同一包裹内 event_time 必须随 event_seq 递增，防止把历史写成乱序
三个设计要点：
① 客户只有一套：题目说"有些客户可能两者都是"。若把寄件人、收件人建成两个实体集，同一个客户就会有两条记录（数据重复、且无法表达"这个人既寄又收"）。 正确做法是共用 customer，用 sends / receives 两个联系（关系模式里体现为 package 上的两个不同外码），必要时还可以让 sender = receiver（自己寄给自己）。
② 位置用概化：卡车、飞机、机场、仓库属性差很多（车牌/机尾号/三字码/仓号），但都要能被事件的 location 引用，所以抽出超类 location。 本题是全概化 + 不相交，这与上一题（网上书店，重叠概化）正好相反：重叠只能"超类表 + 子类表"，而不相交还可以用"单表 + 判别列 + CHECK"。
③ "当前位置"是派生数据，不建字段：包裹的当前位置 = 历史表中 event_time 最大的那条事件的 location，用视图现算即可； 强行存一列 current_location 会与历史不一致（要么靠触发器维护，要么干脆不存）。
